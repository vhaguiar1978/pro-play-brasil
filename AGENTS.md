# AGENTS.md

## Regra Permanente do Projeto

Este arquivo define as regras obrigatorias para qualquer desenvolvimento futuro do Pro Play Brasil. Toda tela, pagina, componente, secao, fluxo, layout, modulo ou refatoracao deve seguir este documento em conjunto com `PADRAO_FRONTEND_PROPLAY.md`.

## Leitura Obrigatoria

Antes de criar ou alterar qualquer parte do sistema, e obrigatorio:

1. Ler `AGENTS.md`.
2. Ler `PADRAO_FRONTEND_PROPLAY.md`.
3. Aplicar ambos os documentos nas decisoes visuais, tecnicas, estrategicas e de produto.

Nenhuma entrega deve ignorar essas regras, mesmo em ajustes pequenos.

## Identidade do Produto

O Pro Play Brasil e uma plataforma de campeonatos online de games com foco em experiencia premium, alta conversao e percepcao de marca forte. O sistema precisa transmitir competitividade, confianca, energia, profissionalismo e modernidade.

O produto deve atender operacoes e experiencias para:

- Cadastro de jogadores
- Cadastro de times
- Criacao de campeonatos
- Pagina individual para cada jogo
- Pagina individual para cada campeonato
- Inscricao paga
- Controle de pagamentos
- Tabela de classificacao
- Chaveamento
- Ranking
- Upload de resultado
- Area de transmissao
- Integracao visual para links de Twitch e YouTube
- Perfil de jogador
- Perfil de time
- Painel administrativo
- Controle de premiacao
- Certificados digitais para vencedores
- Estrutura moderna para FIFA, Free Fire, Call of Duty, PUBG e outros jogos

## Principios Inegociaveis

### 1. Visual

Todo frontend deve ter visual gamer moderno, profissional, premium e atual.

E proibido entregar:

- Telas simples demais
- Interfaces genericas
- Layouts com cara antiga
- Componentes improvisados sem consistencia
- Paginas sem hierarquia visual clara

### 2. Mobile First

Toda interface deve ser pensada primeiro para celular e depois expandida para tablet e desktop.

Toda entrega deve ser:

- Responsiva
- Legivel em telas pequenas
- Tocavel com conforto
- Rapida
- Organizada por prioridade de conteudo

### 3. Conversao e Produto

Cada tela deve ajudar o usuario a avancar em um objetivo de negocio ou uso real, como:

- Criar conta
- Entrar em campeonato
- Montar time
- Efetuar pagamento
- Acompanhar partidas
- Enviar resultados
- Consumir transmissao
- Administrar operacoes

Nao desenhar apenas "bonito". Toda interface precisa vender, orientar e converter.

### 4. Pensamento Senior

Toda decisao deve ser tomada com mentalidade de especialista senior em:

- Frontend
- UI/UX
- Produto digital
- Landing pages de alta conversao
- Plataformas SaaS premium
- Ecossistemas gamer e e-sports

### 5. Inovacao Continua

Sempre propor melhorias quando houver oportunidade. O objetivo nao e apenas implementar pedidos, mas elevar o nivel do produto.

Sempre buscar:

- Melhor experiencia
- Melhor clareza
- Melhor performance
- Melhor percepcao de valor
- Diferenciacao frente aos concorrentes

## Referencias de Direcao

Usar referencias de mercado apenas para entender padroes vencedores de:

- Plataformas gamer modernas
- Sites premium de e-sports
- Landing pages de alta conversao
- Produtos SaaS de alto padrao
- Paginas de eventos
- Paginas de campeonatos
- Dashboards modernos

Regras:

- Nao copiar layout
- Nao copiar texto
- Nao copiar imagens
- Nao copiar identidade visual
- Nao copiar codigo
- Nao copiar marcas

Referencia serve para aprender estrutura, ritmo visual, hierarquia, UX e padroes de conversao.

## Diretrizes Tecnicas Obrigatorias

Toda implementacao deve priorizar:

- Componentes reutilizaveis
- Codigo limpo
- Estrutura organizada
- Nomes semanticos
- Escalabilidade
- Facilidade de manutencao
- Prontidao para producao

### Padroes tecnicos esperados

- Evitar duplicacao de componentes e estilos
- Centralizar tokens visuais quando possivel
- Criar secoes modulares e reutilizaveis
- Garantir consistencia entre paginas publicas e areas logadas
- Escrever estruturas preparadas para crescimento do produto
- Preservar acessibilidade, legibilidade e performance

## O Que Toda Tela Deve Entregar

Toda tela nova ou alterada deve ser validada com estas perguntas:

1. Esta com cara de produto premium de e-sports?
2. Funciona muito bem no mobile?
3. Tem hierarquia visual forte?
4. Ha CTA claro quando existir objetivo de conversao?
5. O layout evita aparencia generica?
6. A experiencia transmite confianca e modernidade?
7. O codigo esta reutilizavel e pronto para escala?
8. Existe oportunidade de elevar ainda mais a experiencia?

Se a resposta for "nao" para qualquer item, a entrega ainda nao esta no padrao ideal.

## Prioridades por Tipo de Area

### Paginas publicas

Priorizar:

- Impacto visual
- Clareza de proposta
- Conversao
- Prova de credibilidade
- CTA forte
- Performance

### Paginas de campeonato e jogo

Priorizar:

- Informacoes bem organizadas
- Destaque para inscricao
- Status do campeonato
- Chaveamento e classificacao com boa leitura
- Conteudo ao vivo e transmissao
- Experiencia envolvente

### Perfis de jogador e time

Priorizar:

- Identidade competitiva
- Estatisticas
- Historico
- Conquistas
- Ranking
- Facil leitura em mobile

### Painel administrativo

Priorizar:

- Eficiencia operacional
- Claridade dos dados
- Menos atrito em tarefas repetitivas
- Visao rapida de pagamentos, inscricoes, chaves, premiacoes e resultados

## Regra de Execucao

Sempre que qualquer agente, desenvolvedor ou IA trabalhar neste projeto, deve:

1. Consultar este arquivo antes de editar o frontend.
2. Consultar `PADRAO_FRONTEND_PROPLAY.md`.
3. Implementar ja no nivel premium esperado.
4. Evitar solucoes medianas ou apenas funcionais.
5. Sugerir melhorias quando houver espaco para elevar a experiencia.

## Resultado Esperado

O Pro Play Brasil deve evoluir como uma plataforma de campeonatos online com aparencia, usabilidade e percepcao comparavel a produtos gamer premium e plataformas digitais modernas, sempre com foco em conversao, confianca, escalabilidade e impacto visual.
